# Model Card

## Description
- **Model name:** `bike_share_regressor`
- **Task:** Regression (predict hourly bike rental count, `cnt`)
- **Primary framework:** scikit-learn
- **Registry/tracking:** MLflow tracking and model registry used in this repository

## Intended Use
- Internal educational MLOps project for serving and monitoring workflows.
- Supports single and batch inference through FastAPI endpoints implemented in this repository.
- Not intended for policy, legal, or safety-critical decisions.

## Training Data
- Source: Bike Sharing Dataset (hourly) used by project pipelines.
- Features include temporal context and weather-related variables; target is hourly rentals (`cnt`).
- Data preparation and split logic are versioned in this repository (see DVC/pipeline stages and docs).

## Metrics (overall)
- Overall holdout metrics from `docs/subgroup_metrics.json`:
  - RMSE: **66.71**
  - MAE: **45.06**
  - R2: **0.757**

## Metrics (per subgroup)
- Evaluated subgroups: `season`, `weathersit`, and `workingday`.
- Detailed subgroup values and sample sizes are documented in `docs/subgroup_metrics.md` (source: `docs/subgroup_metrics.json`).
- Current artifact shows materially weaker error performance on `workingday=0` vs `workingday=1`.

## Acceptance criteria
- Validation gate from `configs/params.yaml`: `validation.min_test_r2 = 0.70`.
- Current holdout result in this repository (`R2 = 0.757`) satisfies that minimum threshold.

## Drift behavior
- Drift alerting threshold from `configs/params.yaml`: `drift.drift_threshold_share = 0.20`.
- Interpretation and operator runbook are documented in `monitoring/evidently_reports/interpretation.md`.
- Operational policy is reflected in monitoring outputs (`monitoring/evidently_reports/drift_summary.json`): investigate immediately, and trigger retraining when input drift share remains above threshold across consecutive windows.

## Limitations
- Trained on a fixed historical period; performance can degrade under seasonal or behavior drift.
- Subgroup imbalance and operational changes (weather patterns, events, holidays) can reduce reliability.
- Passing `min_test_r2` and staying under the 0.20 drift threshold are guardrails, not guarantees of stable behavior for every hour/context.

## Ethical Considerations
- This model predicts demand, not people; however, allocation decisions based on predictions can indirectly impact service access across locations or time bands.
- Subgroup monitoring is included to identify disparate error patterns across conditions.
- Human oversight is required before using predictions for resource allocation decisions.

## Monitoring
- Serving metrics are exposed to Prometheus, including `bike_inference_total` with an `output_class` label (binned predicted demand for this regression task).
- Drift checks are generated by Evidently reports under `monitoring/evidently_reports/`.
